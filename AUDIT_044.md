## Portable launch follow-up — November 4, 2026

- The owner tried the delivered `b8d4f18` portable and received **“The session helper stopped unexpectedly.”** `launcher.log` recorded `Invalid file descriptor to ICU data received` before worker JavaScript started. Read-only inspection found the main/renderer still running while `icudtl.dat`, `resources.pak`, `v8_context_snapshot.bin` and `resources/worker/worker.mjs` were missing from its extraction directory. This attempt did not reach a gameplay test.
- Pinned electron-builder **26.18.0** uses one temporary extraction directory per build by default. Its portable wrapper removes that directory before extraction and after its child exits. A second invocation can exit through Electron's single-instance check and then remove resources still needed by the first launcher. Existing portable smoke coverage opened only one instance and missed this lifecycle.
- The correction sets **`build.portable.unpackDirName: true`**, selecting launch-unique `$PLUGINSDIR\app` directories in this pinned implementation. Its bundled option documentation incorrectly describes `false` as unique; the actual `NsisTarget.js` condition also maps `false` to a build-fixed directory. Unique directories keep the second wrapper's cleanup separate from the first launcher.
- **Replacement verified locally:** source `87a488be2814fddb62637bb027a3d6d85835541a`, Electron 45.2.1 / builder 26.18.0, 861 staged files. Packaged startup and the complete portable regression passed: second wrapper exits, original runtime hashes remain intact, a fresh worker returns the expected installation validation, and the first launcher closes cleanly. Portable SHA-256: `8495c3d174e8530fffe90dbea103063bcd29265fb20367ccb9305be57f23391d`. Delivered to `build/gameplay-test-044d`; the old 044c CMD now forwards there. Native source/hash are unchanged.
- CI `41876390347` also passed the duplicate-launch regression, 82 code checks and 19 UI checks, but its new update probe failed on a Unicode path comparison. ## Server startup follow-up — November 4, 2026

The owner corrected the initial 044d “Fortnite starts” reply: the launcher instead reported **“Game server could not start.”** This is not a successful gameplay test. The captured 4.2 crash occurred before login with `Cannot Flush Async Loading while async loading is suspended (1)`. `memory.dll` and `reboot.dll` were absent from the dump. Despite `-UserDir`, the game read shared configuration and wrote its log/crash under the global FortniteGame Saved directory. The active global log was later overwritten by modern Fortnite, reinforcing the need to match each launch's exact marker.

The correction removes the ineffective UserDir preparation and restores 0.4.2's backup/process-guarded repair of the actual global borderless-resolution settings. The unused settings-isolation class was removed; its code remains in Git history. No actual game settings were edited during this investigation. The historical same-fatal/mismatched-resolution evidence supports restoring the guard but does not prove the engine's precise initiating cause. The separate HUD Apply crash remains unresolved.
